# Container-width repair report

Release: **0.1.18**. Upstream baseline: **Mermaid.js 12.0.0**.

The [upstream inventory](upstream-container-width-map.md) maps the changed
production stages. Gantt now reads Compose parent content width before
layout, preserves explicit `useWidth` precedence, rounds relative time-scale
coordinates as D3 does, and chooses task-label sides before adding the left
offset. Narrow official output can still overlap labels and date ticks.
Those upstream results remain the comparison target.

Mindmap paint is unchanged. Official Dagre/classic and Native CoSE/Neo are
different configurations. Same-theme probes under both layouts confirm that
classic Redux Color has a filled root and colored edges, while Neo has a
background-filled root and dark edges. Neither style is corrected to imitate
the other. Small roundness, measurement, shadow and coordinate differences
remain under review.

The public `ganttUseWidth` property changes from `Float = 1200f` to
`Float? = null` to represent upstream's undefined configuration. Explicit
numeric callers retain their meaning, including explicit `1200`. Core users
without a parent keep the 1200 fallback; context users can supply
`containerWidth`. Consumers must rebuild against the changed API. Available
widths that cannot yield a finite positive native time domain return a
structured configuration error rather than being enlarged.

Fresh JVM validation: **Core 1100 / Compose 75 passed**, zero failures.
This includes width changes, padding and two-times density through the public
composable, explicit-width precedence, relative label coordinates, zero-date
domain midpoint, and unchanged Mindmap look semantics. Android, iOS Arm64
and Wasm core/Compose compilation passed.
The Kotlin 1.7.21 Android release AAR, legacy publication coordinates,
modern publication coordinates and Desktop debug UI compilation also passed.

The [evidence](assets/container-width-report/evidence.md) contains **2 families,
3 unique sources, 9 configuration scenarios, 18 screenshots and 3 reviewed
contact sheets**. Results: **0 Pass / 9 Review / 0 Fail**. All content checks
pass. All five Gantt scenarios have matching scene size, rounded task
geometry, paint and task-label x positions within 1 logical pixel. All four
Mindmap scenarios retain matching paint, point counts and topology
relationships; subpixel coordinates and rendered endpoints remain Review.
The detail audit includes per-edge direction sequence, bends, port sides,
shared tracks, crossings and rendered endpoints. SSIM is diagnostic only;
the low narrow-Gantt score does not become a visual Pass.

This evidence is separate from the historical 33-family matrix and the
mobile consuming-app reports. Neither has been regenerated by this repair,
and no 1000-case mobile rerun is represented here. Gantt title
weight, text baselines, glyph rasterization, Mindmap corner radius, long-label
wrapping and other previously reviewed minor differences are deferred.
This targeted repair does not establish Stable status.

Reproduce the source/config captures with
`node tools/official-reference/capture-container-width.mjs build/container-width`
and `./gradlew :mermaid-compose:captureContainerWidth`. The first tool needs a
local Chrome executable through `PUPPETEER_EXECUTABLE_PATH`. Run
`python tools/official-reference/container-width-contact-sheets.py build/container-width`
with Pillow, NumPy and scikit-image to generate raster evidence, then run
`node tools/official-reference/audit-container-width.mjs build/container-width`
against the captures and raster evidence; it rejects stale inputs and
preserves Review findings.
